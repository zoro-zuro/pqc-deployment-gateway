# PQC Code Signer & Verifier - Demo Dataset

This directory contains test artifacts designed for demonstrating post-quantum digital signature generation, verification, and tamper detection with **ML-DSA-65** (standardized CRYSTALS-Dilithium).

---

## Artifact Descriptions

* **`app.bin`**:
  Represents a legitimate software artifact / binary built by authorized developers. It serves as the primary artifact for key generation, signing, and positive verification tests.

* **`app.bin.sig`**:
  Represents the post-quantum digital signature file generated by `pqc sign demo/app.bin`. Contains the ML-DSA-65 signature bytes along with integrity metadata (SHA-256 hash, algorithm identifier, creation timestamp).

* **`app_tampered.bin`**:
  Represents an artifact that has been modified after signing (simulating a bit-flip, malicious injection, or unauthorized tampering in distribution). Verifying this file against `app.bin.sig` will immediately fail cryptographic verification.

---

## Important Security Context

> **Note on Scope**:
> This dataset provides a **functional simulation** for testing and demonstration purposes, not a real production executable binary.
>
> Detecting modification of `app.bin` proves cryptographic integrity and signer authentication under post-quantum hardness assumptions. However, this prototype **does NOT claim to protect against every software supply-chain attack**.
>
> In production environments:
> - Signing keys must reside in hardware security modules (HSM) or secure KMS, rather than local disk.
> - Build systems must enforce provenance attestation (e.g., SLSA, in-toto) and transparency logging.
> - A valid signature authenticates that the artifact was signed by the key holder; it does not guarantee that the signed software is bug-free or vulnerability-free.
